# SMIS → BUFF 按金额采购与交易账本 v0.4

输入本次采购金额，启动任务。程序分析SMIS、核对BUFF实际卖单并仅使用BUFF可用资金分批购买，收货方式固定为“让卖家发起报价”。Steam出售由你手动完成，之后添加销售记录。

## 使用顺序

1. 双击本目录 `start.cmd`，打开 **http://127.0.0.1:8769**，保持启动窗口运行。
2. 点击“打开BUFF登录窗口”，在专用Microsoft Edge浏览器里自行登录，再检查绑定账号。
3. 设置并保存正确的17位SteamID。首次可先预检，确认页面、报价、BUFF可用资金及“让卖家发起报价”可用后，在设置中开启自动采购。
4. 输入任务名称和本次采购金额，点击“创建采购任务”，再点击“开始采购”。
5. 程序连续分批核价、采购和保存订单。已付金额与未决预留合计不得超过本次预算。剩额不足下一件或本轮没有合格报价时结束，保留余款；不会放宽比例凑满金额。
6. 收货后自行在Steam出售。在“交易账本”选择采购批次，填写出售件数、本次成交总额、手续费、时间和可选成交编号。

每个任务预算独立，不设累计1000元上限，不需要录入Steam钱包余额或设定余额目标。销售收入不会补回任何采购任务预算。首次账户购买、收货仍需小额实测，本次程序验证没有使用真实资金。

## 采购控制

- BUFF现金成本 / Steam当前求购净额估算严格小于0.70；Steam日成交量至少30，可收紧这些条件。
- “运行设置 → 采购条件”可自定义单件最低采购金额，单位元、最多两位小数，默认0表示不限。按BUFF每件实际买价核验，等于最低金额仍可采购；不是Steam卖价或整批采购总额。保存后生效，已购记录不受影响。降低最低金额后，启动采购会重新读取此前按较高金额筛选的行情。
- 设置最低金额后，行情候选及BUFF实时卖单均排除低于该金额的物品。若最低金额过高导致没有合格报价，本轮任务结束并保留余款，不降低该金额凑满预算。同一商品的BUFF最低卖单低于底价时跳过该商品，避免批量购买页面自动选中低价卖单。
- 净额采用历史SMIS保守估算，不保证未来Steam实际到账。报价按逐条更新时间过滤，默认30分钟有效。
- 每次最多查询5页，分别展示原始记录数、去重报价数、合格候选数、扫描范围、重试与来源时间。有限扫描及排序不代表全市场最优。
- 当前先按SMIS比例排序，再用BUFF实时报价逐件核验阈值；尚未比较多个候选的BUFF实时比例，因此不保证实时最低成本。
- 付款前在BUFF正常网页中核对真实单价、卖单数量、人民币币种、收货账号、每轮总额。默认每轮最高20元，单饰品在途及未售上限10件，均可配置。
- 付款仅使用页面明确可用的“BUFF可用资金”，收货仅选择“让卖家发起报价”，以配合平台自动收货；不会自动改用其他付款方式或自行发送报价。请保证BUFF可用资金充足，并保持自动收货可用。
- 付款或收货方式不同时满足上述要求的饰品自动跳过，继续检查其他候选，不终止整次采购。看板显示最近跳过原因，运行日志保存每次跳过记录；本轮没有满足条件的候选时结束并保留余款。
- 付款前价格、数量或总价变化时，等待对应卖单响应及页面金额更新。确认没有发出付款请求后取消旧预留、自动重新核价，按新价格和任务剩余额度调整件数；单件底价、严格成本比例和预算仍须满足。同一饰品连续3次不稳定时暂时跳过并寻找其他候选，全部不稳定则暂停任务，稍后可点击继续。
- 任何付款请求已放行或已有订单，结果不明时仍冻结预算，不能当作报价变化自动重买。
- 网络、登录、验证码、页面结构或实际收货操作异常会暂停为“需要处理”；付款结果不明会冻结预算，不盲目重试。付款前确认不支持指定交易方式的饰品只跳过，不能把已提交付款后的异常当作未采购并继续重买。
- 暂停后不会提交新付款；已提交的本轮仍须核对。未决订单处理完成后，可继续本任务。
- 当前活动任务结束后再运行另一个任务。可提前创建待运行任务，但不会同时并行扣款。
- 重启后正在运行的任务暂停，需手动继续；提交期间中断的采购恢复为结果不明，预算不会丢失。

自动刷新行情可以常开，但只刷新不会启动采购。只有明确运行的任务且自动采购已开启，程序才会使用BUFF可用资金付款。

## 看板与账本

采购看板显示本次预算、已付款、预留、剩余金额、件数、任务状态以及实际订单。交易账本显示累计采购、收货、已售及未售件数、采购成本、Steam成交总额、手续费、净入账与已售成本比例。

同一采购批次可分次出售，禁止超出已收货且尚未记录出售的数量。未确认收货不能录入销售。成交编号可防重复；重复记录也可修改或撤销，撤销会恢复账本未售数量并留审计记录，不影响真实平台交易。

销售成本按本批采购明细顺序归集；没有逐单明细时按批次实付金额用整数分分摊。修改或撤销销售会重新计算，确保全部出售时归集成本等于原批次采购成本。

已售现金成本比例 = 对应已售采购成本 / Steam净入账。Steam净入账为Steam平台余额，不展示为可提现现金利润。未收货或未售库存估值不计收入。

旧版采购、订单、账本事件及钱包记录保留并迁移。历史已售但没有销售金额的记录单独列为待补录，不算作当前物理库存、不虚造收入；可在对应批次补录销售。

支持完整账本CSV、销售CSV和JSON备份。正式数据库为 `data/funding.sqlite`；专用浏览器登录目录为 `data/buff-profile`，不要分享该目录。关闭程序后备份整个data目录。

## 跨电脑编辑

通过GitHub仓库同步源码。另一台电脑克隆仓库后，运行 `setup.cmd`、`start.cmd`。换电脑前提交并推送，开始编辑前拉取。详细步骤见 [跨电脑同步说明](CLOUD_SYNC.md)。

交易账本、运行设置及BUFF登录资料保留在各电脑的本地 `data/`，不会上传到GitHub。

## 环境和运行

需要Node.js 22.13或更新版本，建议Node.js 24。SQLite为内置模块。Playwright优先从本项目加载，也可使用此电脑已有的Codex运行时；提示浏览器组件缺失时运行 `setup.cmd`。默认使用已安装的Microsoft Edge，可用 `BUFF_BROWSER_EXECUTABLE`指定兼容Chromium路径。

- `start.cmd` / `node server.mjs`：正式版，8769端口。
- `demo.cmd`：独立虚构演示，8770端口，不能据此真实交易。
- `node --test`：预算、订单、账本、存储、HTTP、行情适配测试。
- `npm run check:trade-mode`：真浏览器在本地虚构页面验证BUFF可用资金名称识别、付款编号保护、不支持方式的跳过、卖家报价逐单确认，以及失败时保留付款。
- `npm run check:quotes`：本地虚构交易验证延迟报价与页面同步、涨价重算件数、持续波动的跳过/暂停、未知付款冻结。
- `npm run check:browser`：本地虚构BUFF页面付款守卫测试。
- `npm run check:dashboard`：浏览器验证最低单价保存及低价过滤、等于阈值、恢复不限，以及创建任务、预检、付款结果冻结与核对后的继续入口、模拟采购和销售增改撤销。
- `npm run check:workflow`：本地虚构卖单＋真实浏览器＋真实后台的连续采购与销售账本全流程测试。
- `scripts/verify-live.mjs`：真实SMIS、看板按钮、金额任务创建和未登录BUFF检查；独立数据、采购关闭，不执行付款。

浏览器测试需要已安装的Playwright兼容浏览器，或设置 `PLAYWRIGHT_BROWSER_EXECUTABLE`。关闭启动窗口停止程序；关闭BUFF专用窗口停止网页自动化。本版未安装开机服务或系统通知，不修改系统代理。

## 文件

- `smis.mjs`：公开行情读取、校验解析、可观测重试与分页。
- `core.mjs`：任务预算、逐件深度、采购状态和手工销售成本归集。
- `store.mjs`：SQLite事务、提交意图、幂等、迁移及审计。
- `buff-browser.mjs`：BUFF正常网页核价、BUFF可用资金付款、“让卖家发起报价”及收货核对，不接入付费开发者API。
- `server.mjs`：任务连续执行、行情刷新、收货核对和本地API。
- `public/`：采购看板与交易账本。
